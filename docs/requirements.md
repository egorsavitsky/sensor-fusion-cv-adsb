# Сопоставление препятствий в зоне аэродрома

На каждый кадр СТЗ программа подбирает соответствия среди объектов АЗН-В. Один объект каждого источника может войти только в одну назначенную пару. Для проверки доступны размеры и координаты препятствий из лога СТЗ. Синхронной записи АЗН-В нет, поэтому второй поток строится по опорным координатам с заданными ошибками, задержкой и потерями.

## Входные данные и координаты

Одна строка TSV описывает одно наблюдение. Одинаковые `Timestamp(Ms)` образуют кадр. В программе время отсчитывается в секундах от первой метки записи.

| Поля лога | Как используются |
| --- | --- |
| `ID`, `Class` | Идентификатор внутри источника и класс. 0 — самолёт, 1 — машина. |
| `Size.X/Y/Z` | Ширина, высота и длина объекта в метрах. |
| `Position.X/Y/Z`, `Direction.X/Y/Z` | Положение в метрах и вектор направления в осях камеры. |
| `Obs.Lat/Lon/Alt`, `Obs.Yaw` | Опорное положение объекта и его курс для модели АЗН-В. |
| `Own.Lat/Lon/Alt`, `Own.Yaw/Pitch/Roll` | Положение и ориентация ВС, на котором установлена камера. |

В логе широта и долгота заданы в радианах, высота — в метрах, углы ориентации — в градусах. Для расчёта высота принята эллипсоидальной, то есть отсчитывается от поверхности эллипсоида WGS84. Если поступит реальная запись с барометрической высотой, её потребуется привести к общей системе высот.

У камеры ось X направлена вправо, Y вверх, Z вперёд. Смещение блока относительно точки собственного положения ВС составляет (0; 1,1; 15,5) м, смещение камеры внутри блока нулевое. Эти значения используются по умолчанию. Параметр `--calibration-frames N` позволяет отдельно оценить смещение по первым N кадрам. Эти кадры исключаются из оценки качества.

Опорные точки переводятся из WGS84 в геоцентрические декартовы координаты (ECEF), затем в местные оси восток, север, вверх (ENU). Начало ENU — первое положение собственного ВС. Для наблюдения СТЗ учитываются установка камеры и ориентация ВС. По умолчанию `Position` принимается за центр объекта. Чтобы получить основание, программа вычитает половину высоты вдоль местной вертикали. Для измерения от основания есть `--position-anchor base`. Курс отсчитывается от севера по часовой стрелке.

## Как выбирается пара

1. **Время.** В обычном режиме на момент кадра доступно последнее доставленное сообщение. Его координаты удерживаются до `--max-age` секунд с момента измерения. При разборе готовой записи `--offline` разрешает взять соседние измерения до и после кадра, даже если второе пришло позже. Координаты и размеры интерполируются линейно, курс — по кратчайшей дуге. Если промежуток больше `--max-gap`, остаётся только последнее достаточно свежее измерение.
2. **Пересечение.** Основания объектов представляются прямоугольниками шириной `Size.X` и длиной `Size.Z`, повёрнутыми по курсу. После отсечения одного контура границами другого вычисляется общая площадь S. Степень совпадения равна `IoU = S / (S₁ + S₂ − S)`. Два квадрата 2 × 2 м со сдвигом на 1 м имеют S = 2 м² и IoU = 1/3. Полное совпадение даёт 1, касание ребром или вершиной — 0.
3. **Отбор.** В отчёт о пересечениях входят пары с IoU > 0. Для назначения требуется также `IoU >= --overlap-threshold`, совместимый класс и положительное перекрытие интервалов от основания до верха обоих объектов. Неизвестный класс допускает пару с любым классом. Высота проверяется отдельно от площадного IoU.
4. **Назначение.** По умолчанию жадный алгоритм берёт свободные пары по убыванию IoU. Режим `--assignment optimal` использует венгерский алгоритм. Он сначала максимизирует число допустимых пар, затем сумму их IoU. Например, если самолёту A подходят X и Y, а самолёту B подходит только X, выбор A–Y оставляет возможность назначить B–X.

В режиме `--metric distance` для отбора используется трёхмерное расстояние. Программа сначала проверяет разности по осям, затем сравнивает сумму квадратов с квадратом порога. Квадраты считаются умножением, корень нужен для вывода расстояния выбранной пары. Матрица преобразования камеры готовится на кадр и используется для всех его объектов. `--benchmark` сверяет выбранные пары и сравнивает время двух вариантов жадного расчёта расстояния на одних и тех же кадрах.

## Требования и проверка

| № | Требование | Проверка |
| --- | --- | --- |
| R01 | Читать TSV по заголовкам, сохранять пустые кадры, указывать строку с ошибкой. | Чтение тестовых записей и полного лога. |
| R02 | Применять смещение камеры (0; 1,1; 15,5) м без калибровки по умолчанию. | Сверка параметров запуска и координат. |
| R03 | Учитывать положение и ориентацию ВС при переводе координат и направления в ENU. | Контрольные точки WGS84 и повороты осей. |
| R04 | Моделировать самолёт и машину с разными габаритами и курсами. Сохранять атрибуты у обоих источников. | Двухобъектный пример и выгрузки измерений. |
| R05 | Вычислять площадь пересечения и IoU в диапазоне [0, 1]. | Сдвиг, поворот, вложение и касание прямоугольников. |
| R06 | Принимать порог от 0 до 1 включительно. При нулевом пороге учитывать положительную общую площадь. | Порог на границе, слабое пересечение и одинаковые повёрнутые основания. |
| R07 | Назначать пары один к одному по измерениям. Опорные ID использовать только для оценки. | Неоднозначные пары и сравнение с полным перебором. |
| R08 | Показывать прохождение порога, совместимость классов и высот и итог выбора пары. | Флаги в терминале и в таблице пересечений. |
| R09 | Учитывать время доставки, срок годности измерения и допустимый интервал интерполяции. | Сообщения с задержками и пропусками. |
| R10 | Для пары печатать время, ID, класс, координаты, габариты и курс обоих объектов, IoU и признак IoU > 0. | Разбор строк консоли в тесте командной строки. |
| R11 | Считать кадры, пары при выбранном пороге, назначения, наблюдения и уникальные ID обоих источников. | Сверка итогов с построчными выгрузками. |
| R12 | Сохранять пересечения, назначения, объекты без пары и измерения источников в CSV. | Сверка полей и числа строк CSV. |
| R13 | Воспроизводить модель при одном seed и одной реализации стандартной библиотеки. Изменение потерь должно сохранять шум общих измерений. | Сравнение модельных потоков с разными потерями. |
| R14 | Описать назначение, параметры и результат функций, пояснить вычислительные блоки в исходниках. | Просмотр заголовков функций и комментариев. |

## Контрольный запуск

Оба примера рассчитаны с MinGW GCC 6.3.0, seed 42, порогом 0,1 и `--assignment optimal`. Задержка доставки — 0,2 с, период сообщений — 1 с, калибровка и офлайн-интерполяция выключены. В примере с двумя объектами СКО шума по каждой горизонтальной оси равно 0,5 м, по вертикали — 0,1 м. Охват полный, потерь нет. Для записи СТЗ соответствующие значения — 3 м, 2 м, охват 80% и потери 10%.

| Показатель | Самолёт и машина | Полный лог СТЗ |
| --- | ---: | ---: |
| Кадры | 12 | 23 725 |
| Наблюдения СТЗ / АЗН-В на кадрах | 24 / 22 | 424 157 / 566 173 |
| Уникальные ID СТЗ / АЗН-В | 2 / 2 | 63 / 52 |
| Пары с IoU > 0 (`positive_pairs`) | 24 | 379 446 |
| Пары с IoU ≥ 0,1 (`threshold_pairs`) | 22 | 310 301 |
| После проверки класса и высоты (`eligible_pairs`) | 22 | 295 451 |
| Назначения один к одному (`matches`) | 22 | 288 347 |
| Из них верных по опорным ID модели | 22 | 286 684 |

Одно доставленное сообщение АЗН-В может использоваться на нескольких кадрах. Этим объясняется разница между числом сообщений и числом наблюдений. В примере с двумя объектами к первому кадру ещё ничего не доставлено. На полном логе верны 99,42% назначений. Из 342 050 доступных опорных пар найдено 83,81%. Среднеквадратическая ошибка координат СТЗ относительно опорных точек равна 3,28 м. Эти числа характеризуют эксперимент с модельным АЗН-В.

В PowerShell `.\build.ps1 -Test` запускает тесты C++ и проверку на вертикальное разделение объектов. Команда `python tests/test_cli.py build/fusion_core.exe` дополнительно сверяет вывод и CSV. Примеры таблиц лежат в [data](../data/README.md).
